## Implementation decisions (Phase 0)

| Date | Decision | Rationale | Supersedes |
| :-- | :-- | :-- | :-- |
| 2026-09-20 | Keep scanner packages as `internal/scan` + `internal/domain` rather than the `internal/probe` / `internal/detect` / `pkg/domain` split suggested in §16 | At Phase-0 size, probing and detection are one bounded concern and splitting them buys nothing. `pkg/domain` implies a public API we do not offer yet; `internal/` keeps it unexported until the control plane needs to share it. Recorded so contributors and agents stop re-litigating it against §16. Revisit when the L2 collector lands and genuinely shares types. | — |
| 2026-09-20 | Probe per **port**, not per check; attribute the service from which health path returns 2xx | vLLM and Triton both default to 8000. Probing per check dialed shared ports twice and made a host with filtered ports cost `timeout × len(checks)`. Per-port probing fixed both, and 2xx-on-own-health-path is a reliable discriminator. | — |
| 2026-09-20 | No Go PDF library; the HTML report carries `@media print` rules and `make report-pdf` shells out to headless Chrome | A PDF dependency would cost the zero-dependency static binary, which is what makes ray-guard air-gap-deployable and handable to a security lead (§15, P4). Chrome is optional and local; the scanner never needs it. | — |
| 2026-09-20 | The P9 benchmark snapshot is a **local file with zero network egress**, not opt-in telemetry | Network telemetry would need a receiving endpoint that does not exist, and would give the scanner a phone-home surface to justify in every CISO conversation — for no benefit before there are buyers. A local file the operator chooses to send preserves the flywheel and keeps P4 true by construction. Revisit if volume makes manual collection the bottleneck. | — |
| 2026-09-20 | Host IDs in the snapshot use a **single-use random salt** per snapshot | Makes host identifiers unlinkable across snapshots. Costs longitudinal tracking, which an aggregate benchmark index does not need. | — |
| 2026-09-20 | Grade thresholds stay provisional and are stated as such in the report footer | Publishing a confident grade we have not validated with buyers would be the exact "sophistication ahead of demand" failure P2 exists to prevent (§10.0). | — |
| 2026-09-20 | An open port we cannot identify is reported at Info (`RG-EXPOSURE-001`), never guessed at | Misattributing a service is worse than admitting we do not know. A false "Triton exposed" on a Neocloud's report is how the tool loses credibility in the room. | — |
| 2026-09-20 | Exit codes encode the worst severity found (0 clean, 3–6 by severity, 1 runtime, 2 usage) | Lets a tenant gate their own CI on posture, which is how the tenant-side vantage (§1.5) actually gets used. | — |
| 2026-09-20 | The P3 suite lives in `/test` as a separate CI step, and its guards were verified to fail when a violation was introduced | P3 is existential; a guard nobody has seen fail is not a guard. | — |
| 2026-09-20 | Integration suite runs Ray, Jupyter, MLflow and Ollama as **real containers**; vLLM and Triton stay **labelled fixtures** | Those two ship GPU-bound, multi-gigabyte images that cannot run on a CPU-only host. Promote them if a GPU host becomes available. | — |
| 2026-09-20 | The TLS handshake gets its own bounded deadline, separate from `-timeout` | A peer that speaks TLS answers a ClientHello within a round trip; one that does not never will. Real Jupyter and MLflow accept the connection and wait silently for an HTTP request, so every open plaintext port cost the full probe timeout. Found only by running against real services — Ray rejects a ClientHello in ~1ms, so no mock exposed it. Cut the integration suite 28s→18s. | — |
| 2026-09-20 | Integration tests are build-tagged and run nightly/on-demand, never on `pull_request` | Multi-gigabyte image pulls on every push would tax normal work for a signal that changes rarely. The nightly run is what catches upstream image drift. | — |
| 2026-09-25 | A scan that reached nothing grades `N/A` (inconclusive), never `A+`, and exits 7 | **The false all-clear was the most damaging bug the product could have.** An unresolvable hostname, a dark /24, and a genuinely clean host all produced an identical confident "A+ — No exposure was observed". A typo in front of a buyer, or a DNS change in a tenant's pipeline, would have reported perfect security forever. Host state is now tracked (`responded` / `no-response` / `unresolved`), clean grades require at least one host that answered, and partial coverage is disclosed on the report. | prior grading, which ignored reachability |
| 2026-09-25 | Only `ECONNREFUSED` counts as proof a host is alive | "No route to host" and "host unreachable" also return promptly rather than timing out, so classifying every non-timeout error as "closed" let an empty subnet masquerade as a clean one. Found by the integration suite, which caught the same address reporting differently across two subtests once ARP had failed — a case no unit test would have produced. | — |
| 2026-09-26 | Scan output is written owner-only (`0600` files, `0700` directories) | A report lists exactly which of a client's services are exposed and unauthenticated — it is a map for anyone who wants in. World-readable is the wrong default on any shared or multi-user machine, and a security tool defaulting its own output to 0644 sets the wrong habit. The operator can widen it deliberately. Found by the first `golangci-lint`/`gosec` run (G306). | prior `0644`/`0755` output |
| 2026-09-25 | Renamed `HostsNoResponse` → `HostsUnanswered` rather than relaxing the P3 field-name guard | The guard flagged its own false positive (a count field containing "response"). A blunt guard that occasionally costs a rename is worth more than a clever one that might miss a real payload field. Weakening it to accommodate our own naming would have been the wrong precedent. | — |
| 2026-10-10 | Every third-party GitHub Action is pinned to a **commit SHA** (with a `# vX.Y.Z` comment), Dependabot updates the pins weekly, the release token is scoped to the release job, and the release workflow **verifies the signatures it just produced** before publishing | `docs/threat-model.md` T6 already claimed "pinned actions", but the workflows used mutable major tags (`@v4`, `@v0`) on actions that run inside the job which builds and signs the binaries people point at GPU clusters — a repointed tag is a direct path to a trojaned release. Pinning without Dependabot would just trade tag risk for staleness. Self-verification matters because the release body instructs people to run `cosign verify-blob`: a signing step that silently produced an unverifiable signature would otherwise be discovered by the first person who took that instruction seriously. | tag-pinned actions; workflow-level write token |
| 2026-10-10 | `golangci-lint-action` v6 → v9, with the linter pinned to `v2.14` rather than `latest` | Action v7+ is required to drive golangci-lint **v2**, and `.golangci.yml` is now a v2 config — so the lint job could not have enforced the file it was pointed at. `latest` is not used because a future golangci-lint v3 would silently turn the gate off again in exactly the same way. A lint gate that cannot fail is worse than no gate: it reports green. | — |
| 2026-10-10 | `go.mod` stays at `go 1.22` while CI builds on Go 1.27 | The `go` directive is the **minimum needed to build**, not the newest available. CI still uses the newest compiler so we get its checks. | a brief bump of go.mod to 1.27 |
| 2026-10-10 | The report footer states that grades are provisional **without citing `CLAUDE.md 10.0`**; the "a /24 completes in well under a minute" claim in `docs/assessment/objections.md` and the authorization template is replaced with the bound the code actually gives (~8 waves of 32 hosts x the probe timeout; measured 16.3s at `-timeout 2s`); and the four leaks planted to confirm the P3 suite fails are written up at the top of `test/metadata_only_test.go` | Found by reading the buyer-facing surface as a skeptic, which was the last open item on the publishing checklist. An internal engineering-document reference inside a deliverable handed to a security lead means nothing to them and invites a question about a file they will never see. The timing claim was exactly the kind a reviewer checks with a stopwatch against a filtered /24 - where it is ~30s at the default, which is true but is not "well under a minute". | 2026-10-10 | Only `internal/scan` may import `net`, `net/http`, `os/exec` or `syscall`, enforced by `TestOnlyTheProbeMayReachTheNetwork` in the P3 suite | The README, SECURITY.md and threat model all tell a CISO that ray-guard cannot phone home *because there is no such code path* - a claim about every future version, which until now rested on nobody adding one. `internal/benchmark` is the pointed case: its output is the one artifact designed to be shared with us (P9), so "write a local file" and "POST it somewhere" are a one-line difference. | 2026-10-10 | The `-out` directory and the `-benchmark-snapshot` path are checked for writability **before** any probing starts; a failure exits 2 (usage), not 1 | Previously a scan ran to completion and *then* failed to write, discarding everything. | 2026-10-10 | `-cidr` and `-ports` are fuzzed, nightly in CI (`make fuzz`), with the seed corpora running in `make test` | These two parse strings an operator pastes on a command line, and `ExpandCIDR` does arithmetic on prefix lengths including a left shift. | 2026-10-10 | Added `RG-TORCHSERVE-001/-002`, `RG-SGLANG-001`, `RG-DCGM-001`; **8080 is swept but never attributed**; TorchServe's inference port is not named from `/ping` | Breadth is the wedge's value - the blind spot is "AI infrastructure ships control planes that assume a trusted network", and one example is a bug while two are a pattern. | 2026-10-10 | The report carries an operator-supplied `-label` and the host the scan ran from; **neither exists as a field on the benchmark snapshot** | Three reports from three engagements were previously indistinguishable attachments, and a "filtered" result read a month later had nothing to say about where the scan stood - which is the first question, because scanning from the wrong side of a firewall is the single most likely explanation. | 2026-10-10 | TorchServe is promoted from fixture to a **real container** (`pytorch/torchserve:0.12.0-cpu`, 1.9GB, CPU-only), run twice - exposed, and token-protected as a negative control. | 2026-10-10 | Prometheus-style endpoints (`triton-metrics`, `torchserve-metrics`, `dcgm-exporter`) are **exempt** from the wildcard control, by a named list with a test that it only contains real services | Real Triton's metrics server answers 200 on any path - normal for an exporter, and found only by promoting Triton to a real container. | 2026-10-24 | Ctrl-C cancels the scan and still writes the report: probing stops at once, targets never dialed are absent rather than listed as unreachable, probes abandoned mid-flight are discarded, and the result is marked `Interrupted` - which makes `A`/`A+` unreachable and exits **130** | Previously SIGINT killed the process and threw the whole run away, so "say stop at any point and I'll stop" (`docs/assessment/runbook.md`) quietly cost the operator the scan and a second authorization window to recover it - which is pressure, in the room, not to stop. The correctness half is the same principle as the 2026-09-25 false-all-clear row, in a different shape: a cancelled probe reports "no response", and a cancelled resolver reports "unresolved", so the naive fix would have printed a customer's healthy hosts as unreachable and then graded the sweep clean on 4 of 254 targets. The handler detaches after the first signal so a second Ctrl-C kills immediately: an operator who wants out now must get out now. | 2026-10-24 | A malformed `-buckets` entry exits 2 before any probing, instead of printing to stderr mid-sweep and being dropped from the report | Found while finishing the interrupt work, in the same validate-before-the-network family as the 2026-10-10 output-path row. | 2026-10-24 | A probe that fails inside the scanner (`EMFILE`/`ENFILE`/`ENOBUFS`/`EADDRNOTAVAIL`) is not recorded as a port state: the port yields no observation, the host is reported as `probe-failed` rather than "no response", and the run is marked degraded - no clean grade, exit 7, a banner naming the cause and the fix. `-concurrency` is also clamped to what the local open-file limit sustains | **Measured, not theorized.** With `ulimit -n 128`, a /24 of the demo cluster graded **C with 3 findings** where the same scan at a normal limit graded **F with 19** - and the unauthenticated Ray dashboard was reported as an *unidentified service on 8265*, because the TCP dial got a descriptor and the HTTP GET did not. Nothing in the report said anything had gone wrong. This is the same harm as the 2026-09-25 false all-clear reached from the other direction: there, absence of coverage read as absence of exposure; here, our own resource limit read as a quiet network. The clamp exists because the better outcome is not to get there at all: after it, the same 128-descriptor scan returns F with 19 findings and zero probe errors (4m1s instead of 17s, which is the right trade - a constrained machine gets a slower correct scan, not a fast wrong one). The degraded path remains as the backstop for what the clamp cannot predict, mainly ephemeral-port exhaustion on large sweeps. Verified against a real `EMFILE` from a real dial (`TestProbeHostUnderDescriptorExhaustion`) rather than a synthesized error, because the kernel is the only thing that can prove the classification. macOS matters here: its default soft limit is 256. | reporting a local probe failure as a filtered port |

| 2026-10-24 | The scanner negotiates down to **TLS 1.0** (`MinVersion: tls.VersionTLS10`), records the negotiated version in `TLSState`, and raises `RG-TLS-003` on 1.0/1.1. A certificate problem and an obsolete version are now **two** findings on one port, not one | Go's client default of TLS 1.2 is correct for a client protecting its own data and wrong for a scanner. Measured against a server capped at TLS 1.0: the handshake fails, `tlsProbe` concludes "not TLS", the HTTP probe then speaks plaintext to a TLS port and gets nothing, and an unauthenticated Ray dashboard behind an old terminating proxy is reported as an *unidentified open port at Info*. The obsolete protocol - a finding in its own right, and the TLS finding a customer's own auditor is most likely to raise - is invisible for exactly the same reason. Lowering the floor costs nothing on modern services: negotiation still settles on the highest mutually supported version (verified against real nginx: 1.2/1.3, no false `RG-TLS-003`). Nothing confidential is sent either way, which is also why `InsecureSkipVerify` is right here - we verify the chain ourselves afterwards so the *failure class* can be reported. The two findings are split because they have different fixes and travel together in the field: the box with TLS 1.0 on it usually has a self-signed certificate too, and collapsing them means the operator fixes the certificate, re-scans, and only then hears about the protocol. SSLv3 and older are unsupported by Go, so those remain unidentified ports - the stated ceiling of the check. | the TLS 1.2 client floor; one finding per TLS port |
| 2026-10-24 | The integration stack gains a real **nginx TLS proxy** in front of the real Ray dashboard, with a self-signed certificate **generated at test time** (`fixtures/gencert`, `make tls-fixture`) rather than committed | Every TLS test ran against Go's own `httptest` TLS server, and this suite exists because our mocks agree with us - real Jupyter's accept-and-hang and real Triton's blanket-200 metrics endpoint were both found by running the real thing. "TLS in front of an orchestrator that is still unauthenticated behind it" is also the most common half-measure in the field, so it belongs in the demo as well: it is now the third critical on the demo report, and the talking point writes itself (encryption does not authenticate anyone). The key is generated because a security product shipping a `.pem` in its own tree invites exactly one question in review, and "it's only for tests" is a worse answer than not having one. nginx:alpine has no `openssl` binary and a test suite should not assume the host does, so the generator is 90 lines of Go with no dependencies. | 2026-10-24 | Corrected the same day: what bounds probe concurrency is the **hard** `RLIMIT_NOFILE`, not the soft one. Since Go 1.19 the runtime raises the soft limit to the hard limit at startup, so the low soft defaults everyone quotes - macOS's 256 - are raised before the scanner runs | The row above, the code comment and a draft release note all said macOS's 256-descriptor default made this a common case. The original experiment was still valid because it set *both* limits (`ulimit -Sn 128; ulimit -Hn 128`), which is why the preflight row records that exact command - but the stated reason the bug mattered was wrong, and a wrong reason is how a correct fix gets reverted later by someone who checks. Caught by verifying a claim in a buyer-facing release note before publishing it. | the macOS soft-limit justification |
| 2026-10-30 | A `-targets` / `-targets-file` entry that is not a host (`https://10.0.0.5:8265`, `10.0.0.5:8265`, a CIDR block, a trailing `#` comment, `10.0.0.256`) is rejected before anything is dialed, exit 2, naming the host or the flag the operator probably meant; the file case names the line number | **Measured:** `-targets https://10.0.0.5:8265,127.0.0.1` graded **A+ (100/100) and exited 0**.
